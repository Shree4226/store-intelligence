# System Architecture

Store Intelligence is split into two main parts: a detection pipeline and a FastAPI backend.

The detection pipeline reads store video, detects and tracks people, assigns visitor IDs, and writes retail analytics events as JSONL. The API layer ingests those events into an in-memory datastore and exposes health, metrics, funnel, heatmap, and anomaly endpoints.

# Detection Pipeline

The detection pipeline uses YOLOv8 for person detection and ByteTrack for tracking people across frames. The entry camera pipeline identifies movement through an entry polygon, assigns a stable visitor ID through the session manager, and creates events such as `ENTRY`, `EXIT`, `ZONE_ENTER`, `ZONE_EXIT`, `ZONE_DWELL`, and billing queue events.

The session manager keeps active and closed visitor sessions. This separates long-lived `visitor_id` values from tracker IDs, which may change or disappear between frames.

# Event Flow

Events are generated by the detection pipeline and written as one JSON object per line in JSONL format.

Each event follows the common schema:

- `event_id`
- `store_id`
- `camera_id`
- `visitor_id`
- `event_type`
- `timestamp`
- `zone_id`
- `dwell_ms`
- `is_staff`
- `confidence`
- `metadata`

The API can also load generated sample events and ingest event batches through `POST /events/ingest`. Duplicate `event_id` values are ignored so ingestion is idempotent.

# API Layer

The API is built with FastAPI. It exposes:

- `GET /`
- `GET /health`
- `POST /events/ingest`
- `GET /stores/{store_id}/metrics`
- `GET /stores/{store_id}/funnel`
- `GET /stores/{store_id}/heatmap`
- `GET /stores/{store_id}/anomalies`

The API includes structured JSON request logging with `trace_id`, endpoint, latency, status code, and `store_id` when available. Global error handlers prevent stack traces from being exposed to clients.

# Data Storage

The current implementation uses an in-memory datastore. This keeps the challenge implementation simple and easy to run locally. Events are keyed by `event_id`, which supports duplicate detection during ingestion.

Generated artifacts such as JSONL files, debug videos, and session files are written under `generated/`.

# AI-Assisted Decisions

- YOLOv8 suggested by AI: accepted. It was chosen because it is lightweight, well documented, and practical for person detection on local CPU using the nano model.
- ByteTrack suggested by AI: accepted with modification. The recommendation was accepted for multi-object tracking, but the project wraps tracker IDs with a separate session manager so visitor IDs remain stable at the business-event level.
- FastAPI architecture suggested by AI: accepted. FastAPI was used because it gives simple routing, response models, OpenAPI docs, and easy local testing with minimal boilerplate.
